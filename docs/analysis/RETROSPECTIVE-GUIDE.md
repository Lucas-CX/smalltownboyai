# 复盘数据归档规范

每次值得保留的分析，在 docs/analysis 新增独立日期快照，并更新 manifest.json 和 README；不要覆盖旧观察来制造连续性。

## 必填信息

- 观察日期与截点、平台时区（未核实则明确写未知）、数据成熟度及筛选条件。
- 来源系统、可公开的来源 URL、授权本地原始文件相对路径及 SHA-256；可核验的代码提交和部署结论分开写。
- 指标定义、单位、分母、去重方式及排除规则；流量、注册、订单实收、退款、成本、成功交付分别记录。
- 已验证事实、推断、建议和未知项分开；问题后续修复应链接新记录，不篡改旧结论。
- 数据脱敏过程、删除字段和仍然存在的局限；少量样本汇总不等于严格匿名化。

## 提交边界

只提交复盘必要的汇总数据、公开技术证据、分析方法及报告。客户邮箱/姓名、个人标识、订单和服务商任务号、逐笔记录、精确交易时刻、IP、会话、私有媒体、签名下载链接、凭据、数据库和原始浏览器日志留在授权本地存储。禁止通过改扩展名或整包压缩绕过这一边界。

每次提交先验证 JSON、文内链接、汇总与来源一致，运行 security-scan，并人工检查新增内容。应用代码的测试或历史报告里的通过结论不能替代本次数据审核。

## 如何追溯

从 README 找到日期报告 → 查看 manifest.json 的来源与转换说明 → 用 source_sha256 校验授权本地原件 → 查看 Git 历史确认档案变化。SHA-256 只能验证字节一致，不能证明来源真实、指标正确或原件长期可用。

原件没有上传时，GitHub 保存的是经过选择与脱敏的证据，不保证可重新运行全部原始分析。需要完整原件备份时，应另行选择受控存储及保留期限，不能自动公开到代码仓库。
