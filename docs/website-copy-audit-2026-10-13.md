# 全站文案审查

审查日期：2026-10-13。对象：当前工作区及 `http://127.0.0.1:3187` 的生产构建预览。

## 结论

公开页面已经具备较好的机器可读基础：正文可在 HTML 中读取，核心产品参数大体一致，问题式标题和直接回答较多，价格页能独立提供具体金额，样片页提供输入与输出。当前最大的文案问题是：部分交易和文件状态提示不精确；用户账户区仍带通用 SaaS 模板含义；新增指南重复解释限制，缺少足够的独有操作信息。

这是内容与表达审查，不是推荐概率测试，也不是法律合规认定。不会把技术 SEO 通过、Schema 存在或文案结构清晰换算成 ChatGPT 推荐率。

## 范围与证据级别

- 抓取本地 13 类公开页面的 EN/ZH 版本，共 26 个 URL，均返回 200。逐页读取渲染文本、MDX、首页及价格页文案来源。
- 读取 6 类认证页面的 EN/ZH 初始 HTML，并检查相应组件及错误处理；初始 HTML 不代表全部交互状态。
- 检查 My videos、购买与生成状态文案，以及 settings 下概览、个人资料、账单、付款记录、积分、API Keys、支持工单的代码。没有创建账号、付款或生成视频来触发状态。
- 账户区问题属于源码确认。匿名访问 `/settings` 未显示受保护正文，未声称在真实客户登录态复现。
- 内部 `/admin` 不是本报告的消费者文案或 AI 搜索优化对象；未做全后台页面审查。
- 新增指南尚未上线。本轮线上认证路由请求出现连接错误/403，未据此推断线上文案或全站可访问性。
- 逐页文本保存在忽略目录 `output/copy-audit-2026-10-13/`。本轮仅新增审查报告，没有修改网站文案。

## 优先问题

### P1-01：请求异常提示不能断言没有费用

- 原文：`We could not save your photos. Check your connection and try again. No payment was taken.` / `暂时无法保存照片，请检查网络后重试，未产生费用。`
- 位置：`messages/en.json:959`、`messages/zh.json:959`；调用处 `src/blocks/dance-studio.tsx:476` 和 `:561`。
- 证据：提交生成失败、余额读取失败等不同情况共用该提示；网络异常无法单凭前端错误确定服务端任务和积分状态。用户也可能刚完成积分购买。
- 后果：把生成请求异常说成照片保存失败，把未知账务状态说成未产生费用，并引导立即重试。
- 建议：按阶段分开。草稿失败说明照片未保存；余额读取失败说明暂时无法核对；生成响应不确定说明先查看“我的视频”和积分记录。通用替换可为：`暂时无法确认本次生成状态。请先查看“我的视频”，避免重复提交；有疑问请联系支持。`
- 这是文案与状态处理问题，不能只批量换一个字符串就算解决。

### P1-02：文件到期不等于文件已物理删除

- 原文：`Files removed` / `文件已移除`。
- 位置：`messages/*:947`；`src/blocks/dance-studio.tsx:1100` 对 `job.expired` 与 `deleted` 使用同一文案。
- 对照：隐私政策明确访问到期与异步物理删除不同。
- 建议：到期显示 `下载期限已过` / `Download access expired`；确认删除后显示 `文件已删除`。失效信息不应只引导用户付费重做，应保留支持入口。

### P1-03：账户区仍然讲另一个产品故事

- `src/routes/settings/index.tsx` 在无订阅时显示 `Free` 和 `Current subscription`，并显示 API Keys、硬编码 0 的 API 使用量、`Build your product on top of this engine` 和 `Your app content goes here.`。
- `src/routes/settings/route.tsx` 提供账单、API Keys 等入口；`src/components/site-user-menu.tsx:68` 从用户菜单链接到该区。
- `billing.tsx`、`payments.tsx` 保留订阅及续订分类。它们与本产品“一次购买，无订阅”的定位不协调。
- 建议：概览围绕“可用积分、视频任务、付款记录、帮助”；移除消费者无用途的模板介绍。没有售卖开发者 API 时，不把 API Keys 作为普通用户导航。
- 不把受保护账户页当 AI 索引页；修复主要服务用户信任和操作理解。

### P1-04：政策中的“我的视频”链接指向上传区

- `privacy-policy.en.mdx:18` 和 `refund-policy.en.mdx:18` 及中文对应段落使用 `/#studio`。
- `contact` 页使用 `/#orders`；工作台代码只在 `#orders` 时自动展开视频列表。
- 建议：统一为语言感知的 `/#orders`，同时明确未登录用户需要登录；邮箱支持入口继续对未登录用户开放。

### P1-05：付款后自动继续还是还要手动点击，表述不统一

- `dance.purchase.next`：付款后返回这里生成；`dance.savedcast`：回来继续。
- 套餐说明与新教程：已确认草稿在付款验证后继续生成。
- `src/blocks/dance-studio.tsx:333` 存在草稿恢复后自动 `generate(draft)` 的分支。
- 建议：分状态说明：有已确认草稿时，付款确认后自动继续；仅购买积分时，回工作台选择照片；草稿已失效时重新选照片。不要让所有购买入口共享一句“照片已保存”。

### P2-01：首页“多少钱”没有直接回答多少钱

- `dance.a12` 回答了 1/3/5 条和 150 积分，却没有美元价格。
- 当前 `dancePlans` 的单次 720p 套餐为 $7.90，3 次 $19.90，5 次 $29.90。
- 建议第一句：`一次 720p 生成为 $7.90 USD，无需订阅。也可一次购买 3 次或 5 次生成。` 后面再解释积分和分辨率。
- 金额须来自共享配置，保持可见 FAQ、JSON-LD、价格页与 llms-full 同步，避免四处写死。

### P2-02：新增指南存在内部审计语气

- 例子：`This preset requests...`、`not a tested ranking`、`What this sample does not establish`、`没有经过验证的无水印保证`、`尚未单独验证`。
- 问题：事实边界值得保留，但措辞让用户承担了供应商和验证流程的理解成本。重复出现时，页面的主要印象变成“很多事不确定”。
- 改法：明确提供什么，再用简短“使用前须知”解释相关限制。
- 例：`This preset requests a 14-second...` → `Create a 14-second vertical dance video from two photos.` 若实际时长只能保证近似，再以真实交付证据统一写 `about 14 seconds`，不能凭文案选择改变产品事实。
- `watermark-free output is not a verified guarantee` → `We do not guarantee watermark-free output.` 中文：`目前不保证成片无水印。`
- 样片标题可改为 `从两张角色图到完整舞蹈视频`；正文保留“虚构角色”和“原曲后期添加”。
- 这包含上轮新写页面需要改进的部分，不应把“信息真实”当成“表达已经成熟”。

### P2-03：多篇页面重复同一组注意事项，独有信息不够

- 总览、教程、猫咪舞、照片、比较和样片反复出现 14 秒、红围栏、原曲后期、外观变化、未验证等信息。
- 每篇都能保持必要事实，但应承担不同任务：总览帮选路；教程演示操作；照片页给规格和裁切示例；样片页给输入输出；购买比较页给决策表。
- 不主张删掉所有限制，也不认定重复内容一定导致搜索惩罚。问题是用户阅读收益和可引用信息密度不足。

### P2-04：照片指南缺少最具体的上传答案

- 指南写“处理上传提示”，却没有直接列出当前 UI 的 20 MB、至少 240 × 240、长短边不超过 8:1 等规则。
- UI 支持 JPG/PNG/WebP/BMP/AVIF，HEIC/HEIF 是否可解码取决于浏览器。
- 建议增加“文件要求”简表，区分最低技术要求与建议照片质量。补上与条款一致的“人物须成年且同意”。
- 不写未经测试的“推荐最少 1080p 照片”，也不保证高分辨率一定更像本人。

### P2-05：趋势示例与本站交付样片容易混淆

- 首页 `Smalltown Boy video examples` / “更多真人与宠物视频”，紧邻产品工作台。
- 当前已说场景、时长不同，但没有直接明确这组展示是否均由当前服务生成。
- 建议按实际性质命名为“舞蹈灵感 / Trend inspiration”，单独把本站可核对的演示叫“本站模板样片”。
- 不需要添加来源平台、作者或播放量；尊重已有图库呈现要求。这里讨论的是归属暗示，不是要求恢复来源展示。
- 中文“真人”比英语 people 更强，可改“人物”，避免把合成人物说成真实人物。

### P2-06：“订单创建”未区分积分购买与视频任务

- 公开页广泛写“订单创建起 24 小时”。同时产品又强调未用积分不失效。
- 后端视频任务以自己的 `createdAt/expiresAt` 计算访问期，不是把套餐购买时间当每条视频的倒计时。
- 建议明确：`未使用积分不设到期时间。每次视频生成任务创建后，照片和成片的访问期限为 24 小时。`
- My videos 显示具体可下载截止时间，比只显示创建时间更能帮助用户；不能未经改代码把期限写成“完成后 24 小时”。

### P2-07：退款页描述了没有承诺什么，没充分说明怎么处理

- 原文：`No fixed refund deadline or unconditional refund offer is stated here` / `本文未承诺固定退款时限或无条件退款`。
- 建议面向问题组织：生成失败→返还积分；重复付款/扣款异常→联系支持核查；完成但不满意→提交订单与问题说明。
- 受理条件、处理期限、未用积分退款规则目前没有足够明确的产品政策。应由业务确认后再写，不能为了转化擅自承诺退款或时限。
- 这里只审查表达完整性，不判断条款是否满足特定司法地区法律。

### P2-08：英语、中文和系统提示没有完全统一

- 英文套餐 `1 × 720p video` 在多份数量时仍使用单数；中文“条视频”与积分按“次生成”消耗需区分。
- `Checking available credits before quoting` → `Checking your credit balance…`；中文“核对余额，稍后显示报价”可简化为“正在查看积分余额…”。
- `native generated audio` → `AI-generated audio`；“角色配置”→“照片和角色顺序”；“原声”→在本产品语境中更明确的“歌曲原曲”。
- 中文空状态“上传照片后，视频订单将显示在这里”与实际提交生成后才有任务不完全一致，可改“开始生成后，你的视频任务会显示在这里”。
- 订单日期在代码中固定 `en-US`；付款状态直接展示后端 `o.status`，中文用户可能看到英文状态码。
- 注册/重置密码设置至少 8 字符，却没有对应的中文字段校验文案；部分认证错误直接显示第三方英文 message 或 `Request failed`。应统一成可执行的本地化提示。

| Credits           | 更清楚解释充值、消耗、退回、余额；必要时显示当前分辨率大致可生成次数，不能混合不同分辨率                       |
| API Keys          | 代码存在，不代表消费者产品已经正式提供可用开发者 API；无此产品承诺时移出普通用户导航                           |
| Support tickets   | “尽快回复”没有可衡量时间；可保留中性表述，强调提交编号和问题，避免保证尚不存在的 SLA                           |

## 不应误报为当前页面问题的残留

- `common.sign.sign_up_description = Get started for free` 在翻译字典中，但当前注册组件和渲染文本没有使用。可清理，不作为现有误导证据。
- `dance.filesize` 的 8 MB 与当前 20 MB 文案不同，但只找到映射引用，没有确认实际触发路径。当前有效照片处理错误使用 `dance.photo.file_too_large`。不能直接说用户同时看到两个限制。
- 旧测试模式的 20 秒、Coming soon、预览价格、第三角色等键仍有残留；本轮公开页面渲染未见这些内容，不能说当前还在展示预览站。
- `dance.onboarding.example` 的 real photos 字样未找到当前页面调用，不当作已展示的效果承诺。
